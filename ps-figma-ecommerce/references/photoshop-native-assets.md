# Photoshop 原生素材：从完整源内容提取

修复已有 PS→Figma 还原偏差时，同时阅读 [ps-figma-fidelity.md](ps-figma-fidelity.md)。原始智能对象与按 PS 效果合成的显示资产用途不同，透明边距也可能承载源位置。

## 连接与定位

发现当前 Photoshop 工具并阅读 schema。典型能力是 `photoshop_ping`、`photoshop_get_state`、`photoshop_list_documents`、`photoshop_get_layers`、`photoshop_get_preview` 和必要时 `photoshop_execute_script`；具体名/参数以当前工具为准。

- 会话开始验证一次连接；操作前读取状态，记录文档 ID、路径、尺寸、颜色模式与当前层。多个文档时按 ID 固定目标，不凭前台标签判断。
- 若脚本超时，它可能仍在 PS 后台运行。先用工具规定的连接探针确认队列已恢复，再读状态；不要同时追加第二段脚本。
- 原始 PSD/PSB 不覆盖保存。使用副本或新导出文件；新开的嵌入内容也不要无意保存回父智能对象。仅关闭本轮自己打开的临时文档，保留用户原先打开的文件和未保存状态。
- 普通取图不需要生成式填充、AI去背景或栅格化；只有用户的具体任务要求时才使用相应能力，并服从当前工具的专用 recipe 约束。

## AI（.ai）矢量智能对象导出

如果Photoshop智能对象的原始类型是`.ai`，需要分别保留Illustrator母版和Figma可用矢量：

1. 在Photoshop图层面板选中智能对象，使用 **图层 > 智能对象 > 导出内容（Export Contents）**，导出独立`.ai`文件。Photoshop会按嵌入内容的原始格式保存；不要把整张PS画板导出PNG并将其误标为原始矢量。
2. 如需查看或编辑源内容，使用 **图层 > 智能对象 > 编辑内容（Edit Contents）**；Photoshop会按嵌入智能对象的格式交给相应应用，真实`.ai`源通常在Illustrator中打开。仅提取时无需保存；编辑并保存可能更新父PSD/PSB里的智能对象，因此先保留独立AI副本。
3. Photoshop没有每个智能对象各自选择“打开方式”的下拉项。若从资源管理器打开`.ai`时启动了Acrobat或其他程序，可在Windows **设置 > 应用 > 默认应用**中按文件类型找到`.ai`，指定Adobe Illustrator。更改后用一份副本实际测试一次 Photoshop 的“编辑内容”，不要仅凭文件关联设置就假定嵌入对象的路由已生效。
4. 为Figma交付，从Illustrator用 **文件 > 导出 > 导出为 > SVG**。只有当目标就是Illustrator画板边界时才选“使用画板”；否则先核对真实矢量外接框，避免切掉画板外的主体。SVG字体选项若设为轮廓，可保持字形但文字不再可编辑；需要可改文案时保留可兼容的文字或在Figma另建TEXT。
5. SVG导入Figma会转换为可编辑矢量层，但Illustrator专属效果、嵌入的位图、复杂滤镜、混合和字体仍须逐图检查。不要假定`.ai`的全部分层、滤镜和文字状态都一比一变成Figma原生对象。
6. 保留AI原件作母版，Figma SVG作为显示/编辑派生文件。分别记录源文件、目标画板/视口、SVG导出设置、实际像素/矢量边界和核对结果；用Figma预览与AI目标外观对照后再交付。

## 判断“模糊/主体不全”的来源

按以下顺序检查，不先放大现有预览：

1. **父画板或包装画布是否裁切？** 最外层PNG可能已经截掉方向盘边缘、底座或夹具；放大这张PNG不会恢复。
2. **是普通像素层还是智能对象？** 普通像素层的原始 RGBA 就是实际可用信息；智能对象应打开/提取其原始内容。
3. **智能对象里面是否还有嵌套智能对象？** 小包装图中可能藏着大尺寸产品源。对本轮使用的关键素材递归查看，并记录每层尺寸与 ID，不盲扫全部文档。大画布不代表可见主体有效分辨率更高；下一层可能只是屏幕画面、图标或产品的一部分，先确认它仍代表需要的完整对象。
4. **可见导出是否混入旧装饰？** 橙色边框、旧色渐变、旧文字、画板遮罩/滤镜可能属于包装，不属于产品。保留真实产品，边框/底板在 Figma 重建为可编辑层。
5. **真正的小源图？** 找不到更高信息源时报告限制，调整占比；不要通过生成产品或锐化伪装成高清源。

停止递归的条件：已经找到完整像素源/原始摄影，或下一层没有更高的相关信息。记录未解缺口，避免无限嵌套查找或重开同一对象。

## 导出规范

- 识别嵌入文件的真实类型并使用正确扩展名交给Photoshop打开；不能将WebP、PDF兼容AI等内容随意改后缀来导出。导出原始完整内容的 PNG/RGBA。透明背景来自原素材，不承诺任何图片天然透明。
- 分开保留 `native` 和 `display/derived`。独立主体提取默认只裁透明边距，并记录 alpha bbox；精确还原源位置时保留原导出矩形，或用记录的裁切偏移补偿位置。大量空房间/桌下环境可在派生图去除，但完整轮圈、底座、双夹、安装结构等相关主体必须保留。
- 不拉伸。完整主体放进视口时计算：

```text
scale = min(viewport_width / source_width, viewport_height / source_height)
display_width  = source_width  * scale
display_height = source_height * scale
x = viewport_x + (viewport_width  - display_width)  / 2
y = viewport_y + (viewport_height - display_height) / 2
```

  节点宽高与源纵横比一致时 `FILL` 也可完整显示；否则优先 `FIT`。工具名不能代替纵横比与可见像素核查。
- **局部特写是例外，不是裁切错误。** 先确认参考特写部位，再从原图明确裁一块局部，保留裁切坐标。握把/缝线特写不能换成完整小轮圈；如果裁切涉及透明区域，可在 Figma 下方放独立背景色。
- 长边缩小只是显示派生，不是源稿处理。没有平台/性能限制时不任意规定所有图片都缩至固定像素；若需要缩小，保留原生导出、记录缩放及实际展示需求。

## 配件数量与完整主体

- “保留一个/只放一个”首先是实物数量要求，不等于把双件图放进窄裁切框。先检查源素材是否有单件原生对象；如没有，从真实高分辨率源中精确分离目标单件，并核对USB接头、标签、阴影和透明边缘仍完整。
- 局部特写和单件陈列是两种不同意图。只有用户指定特写/特定裁切窗口时才裁产品主体；数量正确、对象比例和可识别轮廓也要分别检查。
- 若素材在Figma中看似只剩半件，先检查节点纵横比、`FILL/COVER`和父级蒙版，再检查素材本身；不要先调整源图或放大裁切框掩盖问题。

## 检查与证据

原尺寸查看产品边缘、alpha、孔位、文字/按钮、夹具和结构。既看透明PNG，也看深浅底上的效果。验证：

- 源和派生纵横比、透明边界、完整主体的对应关系。
- 只裁切时，派生像素是否与原图对应窗口完全一致。
- 仅调色时，alpha与几何是否不变；不把金属中性灰、产品界面和背景一并误染。
- 单个配件是否还是一个完整实物，不能用被裁掉的半件或双件错当单件。

素材索引保留源文档、图层 ID、嵌套链、原始/派生路径、尺寸与变换原因。工具若没有返回图像hash，审计需明确证据是导出记录+本地像素，而不是凭快照臆称绑定已验证。

## 最小脚本边界

优先现有工具。只有原生工具不涵盖打开嵌入内容、递归取源等具体操作时使用 PS 脚本；先用只读脚本确认目标 ID，再对已确认的层操作。不要把没有本机测试的脚本当成万能提取器，PS版本、链接智能对象、画板和遮罩语义可能不同。

每个批次：确认当前文档 → 按ID找目标 → 导出到新路径 → 读回/预览 → 写来源记录。错误时以当前PS状态为准，不重跑整套。大源文件等待期间发送简短状态，不反复发出相同导出请求。
