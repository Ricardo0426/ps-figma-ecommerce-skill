# 导出、检查、需求表回填与交接

## 多语言需求表与源画幅

- 开始排版前，为每个字段标注其角色：最终上图文案、翻译参考、设计说明或示例图片。按用户当前明确指定的目标语言列取文案；中译、外语旧稿和示意图里的字不能混入成图。混合单元格中逐块提取目标语句，保留单位、品牌拼写、兼容条件和随箱配件说明；纯格式符及紧跟翻译重复的碎片不打印。
- 旧表头、产品线名或更早的德语/英语项目标题不能覆盖当前语言要求。若源稿把短句拆成若干文本块，先合并有语义关联的块，再写入交付索引；可更改断行，不能无声改写产品承诺。
- 数字图序、A+编号和表格行是不同字段。尊重缺号：没有行、尺寸和文案的图序不自行补造。
- 源PS画幅与目标表格交付尺寸不同，需要保留原源稿作独立构图参考，并按目标比例重新组织产品、可编辑文案和卖点。不能整体拉伸源稿或直接把旧版外语层当目标文案。已完成且用户指定保护的首图继续保留，不以重建版本替换。
- 格式、JPG容量和页面尺寸只采用当前工作簿或本轮用户说明。其他项目的尺寸/限值不能继承为通用标准。

## 从当前索引导出

交付索引由本轮当前表格/工程校准，不能从旧builder的编号猜。按 `output_id + label + sequence + row + figma_group_id` 联合定位。

1. 保存最终结构快照。核对保护组、可见交付组、当前游戏/特写恢复组、隐藏归档。
2. 分小批按交付组导出原尺寸 PNG。部分超时后检查已落盘文件，补缺失项而非盲重导。
3. 验证实际宽高、图片可读取、alpha及边界。转换JPG使用适合交付的质量；透明部分合成到明确底色，不直接把RGBA存成JPEG。
4. 从同一索引生成联系图/HTML/压缩包，按表格图序排，图上标注板块及图序。保留全尺寸PNG和必要JPG；不任意要求固定quality、图数或格式。
5. ZIP完整性检查只证明压缩包可读，不代表文案/版式通过。分别保存结构、像素、文字、视觉和打包核查结果。

有界检查导出的脚本：

```text
python scripts/check_delivery.py --manifest <delivery-index.json> --root <revision-directory> --report <qa.json>
```

manifest的`files`至少有一个PNG/JPG路径、`width/height`为目标像素、`output_id`唯一。该脚本依赖Pillow，检查文件/尺寸/格式/散列；可按需要指定`--contact-sheet <preview.jpg>`生成带图序的联系图。它不检查真实文案、产品或视觉对齐，必须实际查看。

## 插图与替换是不同工作

### 首次插入成图列

- 先读工作表、合并单元格、列宽行高、浮动图与 `DISPIMG`/WPS cellimages。新增列放用户指定位置，不覆盖意见/参考列，也不移动已有布局来套通用模板。
- 原样保留需求文字与引用图片。嵌入图片而不是写本地路径；等比适配单元格，留边距，列宽/行高仅按需要调整。
- 在可用的当前表格工具中插入；导出后比较所有无关单元格、合并、公式、原生图片及注释。复杂WPS原图在通用导入导出里可能丢失；必要时仅将已验证新绘图/媒体合入原ZIP，而不重写全表。
- 本skill的`replace_xlsx_images.py`只替换已存在的图片，不提供首次建列功能。

### 后续替换图片

先检查表格是否被用户加了新意见/参考，永远从**当前原表**读入，不从上次副本覆盖回去。用户在打开的Excel/WPS里刚添加意见，先确认保存，或通过可信实时通道读取该工作簿；磁盘哈希不能证明内存版本已保存。仅替换本轮需要更新的媒体。

映射JSON示例（相对图片路径以映射文件目录为基准）：

```json
[
  {"row": 10, "image": "exports/material.jpg", "label": "主副图4"},
  {"row": 21, "image": "exports/aplus-material.jpg", "label": "A+图5"}
]
```

先 dry-run：

```text
python scripts/replace_xlsx_images.py --source <current.xlsx> --sheet <sheet-name> --image-column J --mapping <mapping.json> --output <updated.xlsx> --allow-partial
```

以上例子只改两行，因此显式使用`--allow-partial`；完整替换该列全部图片时可省略。不要为满足完整映射把未授权图片加入修改范围。核对行→目标锚点/`DISPIMG`→媒体关系→替换图→尺寸后，追加`--apply`生成已验证的新副本。脚本只修改图片媒体字节，检查所有其他ZIP条目、XML/关系、批注及参考图保持一致。

- 现有PNG不能写入JPEG字节反之亦然；需要改变媒体类型/关系时用适合的原生工具，不能仅改文件扩展名。
- 同一媒体若被其他对象复用，不允许误改参考图。仅当所有消费者都在授权映射中且替换字节完全相同时，共享媒体才可以替换；未知消费者（例如VML/页眉图片）必须保守拒绝。歧义或不同替换内容也要拒绝；先分离引用或使用原生插图操作。
- 默认要求替换图与原图格式、像素宽高相同。已确认改变像素尺寸且仍保持展示比例时可用`--allow-dimension-change`，脚本不会调整锚点、展示宽高或裁切关系，仍需实际查看以防拉伸。
- 自动匹配要求图片锚点起始列/行或cellimages关系可确定。绝对定位图片、多个图片落在同单元格等情况先人工核查，不能随便取第一个。

### 原位同步与文件锁

用户已授权改原表时，dry-run确认后追加`--apply --in-place --backup-dir <revision/backups>`。先生成并验证输出、保存原表精确备份，再原位替换；脚本检查源表是否在处理中被改动。

如果Excel/WPS占用或权限拒绝：保留输出副本，明确`sourceUpdated=false`；不要强制关闭应用、杀进程或重复覆盖。请用户保存关闭，关闭后重新读取源表，重新准备更新以保留新意见，再同步。重新打开/核验实际原表与副本内容一致后才报告“原表已更新”。

## 交接与最新入口

- 更新最新总览/README入口到当前版本；旧内容先备份，不删除历史轮次。链接或路径必须真实存在。
- 把本轮原尺寸图、索引、简短说明和必要源预览打包；不夹带API key、临时日志、无关客户源稿或builder中间产物。
- 声明PS源稿是否保留、Figma实际页面/组、可编辑图层状态、当前图序、表格副本与原表同步状态、源像素限制。
- 图像生成仅保留最终提示词和模型/质量/尺寸元数据即可；不能让生成脚本成为用户审批的替代物。
- 交付答复聚焦用户要求，给实际预览和最新文件。部分完成必须明确哪部分未落盘/未同步；不要将已验证副本说成原表写回成功。

## 暂停与本地归档

用户要求暂停时停止设计写入，按指定范围完成复制和交接；待办列表不构成恢复工作的授权。用户明确“复制和写交接即可、不用检查”时，不继续开展散列核验、全套视觉验收或其他额外检查，完成指定交付后结束。

- 先明确需要复制的本地源目录、历史提取工程和本轮工程。完整工程归档可以保留相关中间素材、诊断记录与脚本；不要误用“仅成图交付包”的筛选规则漏掉工程文件。仍需排除无关项目和凭证，不把“全部”扩成整台电脑。
- 目标目录有原文件时使用独立子目录，保留源目录。避免把目标放在源目录内部再递归复制，或在更新少数交接文件时重跑全量复制。
- 依用户要求决定是否保存 Figma 副本。明确“不保存”后终止副本导出；不要以交接完整性为由继续尝试。已有结构 JSON/截图可作为范围明确的诊断证据，不能包装成完整 Figma 工程。
- 复制磁盘 PSB/PSD 不能恢复未保存的内存修改。记录已观察的文档保存/打开状态；没有证据时说明未知，不声称磁盘副本包含未保存状态，也不为归档擅自覆盖保存源稿。
- 交接写明当前 Figma 文件/页面及目标组、已完成修改、未验收问题、最后对照图/快照的范围与轮次、目录/脚本索引、旧脚本失效点和路径迁移注意事项。运行期 ID、硬编码路径和会创建新节点的操作不能直接重放。
- 若归档前已完成检查，只报告真实结果和覆盖范围；后来新增的交接文档不能自动计入先前的散列统计。若未执行检查，直说未执行，不补写“已校验”。

收尾以用户当前目标为准：“已归档、项目暂停、尚未最终验收”与“设计完成”是不同状态。恢复时先实时读取现场，保留范围外新增内容，再处理交接待办。
