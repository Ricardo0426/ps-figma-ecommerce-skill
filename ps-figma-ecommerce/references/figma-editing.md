# Figma：真实结构、局部修订和状态恢复

## 写入前

用当前可用的 Figwright 读工具确认文件/页面。`ping/get_metadata/get_pages/get_node/get_design_context` 是典型能力，不是固定可用清单；先发现工具并按当前 schema 调用。若返回多个连接，使用文件认领能力固定本轮对象。

已有样式/变量/组件可读取并复用，但海报不必改造成 UI 系统。没有共享token时使用当前工程实际字体、颜色、边距；不能把过去项目的字体或红黑色套进新品牌。新节点遵守实际周边约定。

在修改目录保存：当前目标组完整快照、保护组快照、交付索引以及必要预览。整页结构很大时用有界读取/本地文件，不把巨大JSON放进一次脚本参数。

## 坐标、尺寸和层序

- 有些读工具序列化的是页面空间坐标，有些写工具接收相对父级坐标。**读写文档后再换算**，不要套用历史脚本。首次对一个现有子节点做小范围定位，立即读回确认。
- 组成员改变大小/边界会影响 GROUP 自身bounds。操作后重读父组与相邻节点；没有遮罩不等于一定会溢出，有遮罩也不等于主体完整。
- 含完整画板遮罩的海报组，检查mask范围与后续兄弟层；不要把新层插到mask之前导致无法受控，或将纯背景图误设为遮罩。
- 典型顺序是范围遮罩/底板 → 场景或光线 → 独立氛围和文字保护 → 产品及装饰卡 → 文字。实际层序依局部遮挡关系决定，保护层要在文字下方，不能遮住产品关键部位。
- 新节点和克隆节点先记录工具返回ID，再 reparent/rename/reorder；不要靠创建顺序猜ID或把名称当唯一身份。

## 看懂参考再恢复

对“用之前的布局”先检索历史组和参考原图，确定哪个版本，不能把最新稿当唯一依据。若仍有明确歧义且会实质改变交付，再问用户。

- 图数、PC/Xbox/PS分组、封面长宽、左右/上下叠卡和局部特写是版式含义，不是装饰细节。
- 可复用原版时克隆相关组到目标页面，建立旧ID→新ID映射，保留源组。新组验证通过再隐藏旧稿并更新交付索引。
- 恢复版式不等于恢复已知错误：逐项核对封面与标签，删除旧底条/额外logo等已授权差异。必要文案换行可以改，但不迁入参考中其他型号卖点。
- 原素材与参考构图冲突时，用高清源裁正确的局部，不直接拿烘焙低清成品替换。局部卡底色、描边、圆角、重叠顺序仍独立可编辑。

## 文案排版

先检查措辞是否真的需要改。仅断行需求时只改空格/换行，使用空白规范化比较前后文本；保留文案的词序、单位和条件。

- 保持短介词与后续词、数字与单位、平台品牌词组不被不自然拆开。根据语言使用不间断空格，不机械删品牌原文中的重复词。
- 先设实际字体，再设文本宽度和合适的行高；读回真实height，再分配底框和下一内容块。`HEIGHT` 自动增高仍可能产生孤立末词；`NONE` 固定框可能掩盖文字溢出，两个都需要实际截图检查。
- 不把“所有换行建议”一次机械套用。改一组实际测量，若增行碰到产品/下方文案，优先调整可用宽度、行组和间距，不默认整套缩字。
- 红色渐变正文底部可能暗到读不清，可局部用更亮实色或加强独立压暗。大标题和正文不必共用相同渐变。

## 目标语言、可读字号与源比例转换

- 多语言改版时，目标语言决定最终行长、断行和文字框。其他语种的原图可以帮助判断信息层级、字重和相对字号，但不能直接照搬其框宽/字号，也不要为了塞入旧框而把整套新文案一起缩小。
- 先用最终目标文案设置实际字体，再按实际可用宽度调字号、行距和段落分组；优先重排区块、增加可用文字宽度或调整留白。只在需要的个别节点缩放，并在原尺寸及常用缩略尺寸实看字形是否清楚。
- 目标输出比例与PS源稿不同时，可将源稿作为单独、明确命名的参考组留在画布上；新交付组按目标画幅重新构图。源参考应保留不动，不能把整个源图拉伸来“适配”。导入源文件后需标清哪一组是可交付稿，避免将源语言/隐藏文案误导出。

## 对齐审查：先分清缺陷来源

截图圈住底部不一定是产品没齐：可能是光轨高度重复、黑框贴底或背景纹理导致错觉。先读几何：

- 画板外边距、左右内容边缘、并列卡片top/bottom。
- 产品实际主体底部与透明边距；完整节点bounds不总等于视觉主体bounds。
- 文字底框左右内边距、顶部/底部留白、各栏baseline。
- 侧边红线与**全部正文块**的顶底，而不是只与第一段对齐。
- 装饰线是否经过正文；看原尺寸与常用缩略比例，不只检查坐标。

修最少属性；已经同底的产品不要跟着错误背景一起移动。

## 超时和并发恢复

使用小批节点写入，批量数以实际响应能力调整，不固化为某个神奇值。先记录本批请求、返回值，再继续。

- `batch`报错/超时后不能据此认为完全回滚；重新读目标，可能部分操作已生效。
- 把现有状态与期望逐个对比，只补缺失/漂移属性。创建类操作必须先查是否已存在，防止重复导入。
- 文本与图片导入可能比几何慢。超时不要扩大批次或连发重试；拆成更小操作并读回。
- 用户可能同时在文件里改动。最终审计发现不属于本轮操作的位移/改字时保留当前值，记录差异；涉及冲突时只问具体冲突，不用旧全页快照覆盖。

## 预览闭环

按目标组导出较小比例预览，先看发生变化的图；全套创建/跨图背景修订时检查所有受影响图。最后读取当前结构并核对交付索引，再原尺寸导出。导出工具失败时检查目录中实际成功项，仅补缺失项。

截图成功、模型审美认可、结构审计通过是不同证据。交接分别记录，不用一项替另一项。
